## 二、三家厂商的 Planning（怎么做）

### 1. DeepSeek：作用域路由 = 规划的隔离

| 机制 | 实现 |
|---|---|
| **Scope Routing** | 一个 opaque key 选一层——规划的执行隔离 |
| **评测闭环** | 规划结果被评测 → 反馈 → 修正 |
| **快照回滚** | 规划失败能回滚（后悔药）|

**哲学**：规划 = 可评测、可回滚的执行序列——隔离 + 反馈 + 恢复。

### 2. Kimi：规划引擎（Kimi Work）

| 机制 | 实现 |
|---|---|
| **Scheduling Engine** | Kimi Work 的规划引擎（任务调度）|
| **Swarm 编排** | 多 agent 协同规划（swarm-based）|
| **会话记忆** | 长任务规划跨会话持续 |

**哲学**：规划 = 调度——常驻 agent 的"工作计划表"，多 agent 协同执行。

### 3. OpenAI：Codex 的规划实践

| 机制 | 实现 |
|---|---|
| **任务分解** | Codex 把大任务拆小步执行 |
| **Harness 状态** | 规划中的上下文/状态管理 |
| **Agent SDK** | 编排/步骤管理 SDK 化 |

**哲学**：规划 = 工程——任务分解 + 状态管理，代码化表达。

## 三、三家对比 + 实盘规划视角

| 维度 | DeepSeek | Kimi | OpenAI |
|---|---|---|---|
| **规划哲学** | 可回滚执行 | 调度引擎 | 任务分解 |
| **核心机制** | 作用域 + 评测 | swarm 编排 | harness 状态 |
| **自进化** | 评测反馈 | 技能迭代 | Codex 优化 |
| **实盘适配** | ⭐ 隔离+回滚最稳 | 调度灵活 | 生态成熟 |

### 实盘规划视角（"尽早实盘"）

**交易规划的层次**（Tool Use → Planning）：
```text
战略层：三策略配置（多因子/趋势/做市）——长期规划
战术层：单策略信号 → 目标仓位——中期规划
执行层：订单 → 风控 → 成交——短期规划（PET）
自进化层：实盘结果 → 评测 → 修正规划（EvoTS-Agent 式）
```

**交易规划的特殊要求**：
1. **确定性**：执行层规划不能含糊（DeepSeek 式隔离+回滚）
2. **可干预**：人类在环（监控/止损/暂停）——"可视化 + 干预"前沿主题
3. **防幻觉**：规划不能编造（AutoResearch "insight in, hallucination out"）
4. **RL 优化**：战术层规划可用 RL 训练（Planning × RL）

### 自进化视角（"无限自进化"）
```
自进化编辑规划（AutoSR 式：研究状态空间搜索）
  → 规划决定行动（交易/研究/工具调用）
  → 实盘结果反馈
  → 评测（哪些规划有效）
  → 再次编辑规划（递归）
```
**关键**：EvoTS-Agent（金融时序自进化 agent）证明——**交易规划可以自进化**，
这就是本文的路线。
