> 内容: AI 安全从"模型属性"到"系统工程"的转型 + 最新研究方向

---

## 0. TL;DR

- **AI 安全正在从"模型属性"变成"系统工程"**——agent 普及让安全从"防越狱"扩展到"防失控"
- **三大前沿方向**：①红队/对抗评估（自动化攻击）②对齐/防御（RLHF→更硬的对齐）③可解释/机理（白盒透视）
- **国内代表**：智源 FlagSafe（红队/蓝队/白盒三维平台）+ 腾讯朱雀 AI-Infra-Guard（Agent 安全红队）
- **关键转变**：从"单点拦截"到"持续防御"——安全成为贯穿训练-部署-运行的工程

## 2. 三大前沿方向（深度尽调）

### 方向 1：红队 / 对抗评估（主动暴露风险）
**目标**：从"被动响应"到"主动对抗"——自动化找漏洞

| 子方向 | 内容 | 代表 |
|---|---|---|
| 自动化红队 | AI 自动生成攻击（jailbreak 自动搜索）| 各家 red teaming 工具 |
| 多模态攻击 | 跨图像/音频/视频的越狱 | FlagSafe 全模态评测 |
| 具身智能评测 | 机器人/物理世界安全 | FlagSafe 具身智能评测 |
| 策略性欺骗检测 | 模型故意欺骗/误导 | FlagSafe 红队维度 |
| **Agent 安全红队** | 全栈 Agent 攻击面（工具/权限/记忆）| **腾讯朱雀 AI-Infra-Guard** |

### 方向 2：对齐 / 防御（构建防线）
**目标**：把安全准则变成模型/系统能力

| 子方向 | 内容 |
|---|---|
| 安全对齐（RLHF 进阶）| 全模态安全对齐、偏好学习 |
| 智能体防护 | agent 权限控制、工具调用安全 |
| 毒性缓解 | 输出过滤、有害内容抑制 |
| 网络风险监测 | 网络空间内容风控 |
| **训练-运行-治理** | 安全贯穿全生命周期（FlagSafe 蓝队）|

### 方向 3：可解释 / 机理（白盒透视）
**目标**：理解风险根因 + 修正模型行为

| 子方向 | 内容 |
|---|---|
| 安全机理分析 | 模型为何会"坏"（内部机制）|
| 内部状态监测 | 运行时监控模型状态 |
| 定向干预 | 针对性修正行为 |
| 数据归因溯源 | 训练数据来源追溯 |

## 3. 国内代表（重点尽调）

### 智源 FlagSafe（2026-05 发布）
- **定位**：大模型安全平台（评估-防御-可解释）
- **机构**：智源 + 北大/北邮/北航/上交/中科院信工所/计算所等
- **三维能力**：红队演练（主动发现）+ 蓝队防御（构建防线）+ 白盒透视（解释根因）
- **五条红线**（基于北京 AI 安全国际共识）：
  1. 防范未经批准的自主复制/改进
  2. 禁止不当获取权力/影响力
  3. 严禁协助大规模杀伤性武器
  4. 禁止自主破坏性网络攻击
  5. 防范对监管者的欺骗/误导
- **意义**：中国版"全面安全"标准——从价值红线到核心能力

### 腾讯朱雀 AI-Infra-Guard（2026）
- **定位**：首个全栈 AI Agent 安全红队框架
- **意义**：把安全从"模型层"扩展到"infra 层"（工具/权限/数据流）

## 5. 对研究的启示（p-research 视角）

1. **安全 = 系统工程**：不再是单篇论文问题，是"训练-部署-运行-治理"全链路
2. **Agent 安全是新前沿**：工具调用/权限/记忆是全新攻击面（与 agent harness 工程直接相关）
3. **红队自动化是趋势**：AI 打 AI——与强化学习自我改进方法论同源
4. **国内在加速**：FlagSafe 证明中国团队在做系统性安全研究
